# ASR Evaluation Pipeline

Автоматизированный пайплайн для оценки качества систем распознавания речи (ASR).

## Назначение

Пайплайн решает задачу **объективной оценки качества транскрибации** с использованием стандартной метрики WER (Word Error Rate) и детального разбора типов ошибок.

## Структура

```bash
asr_eval/                          # Оценка ASR
   ├── README.md                      # Описание пайплайна ASR
   ├── evaluate_asr.py                # Основной скрипт
   ├── add_noise.py                   # Генератор шумных аудио
   ├── test_set.jsonl                 # 6 аудиофайлов (clean + noisy)
   ├── asr_results.jsonl              # Результаты прогона
```

## Методология

### Модель

- **faster-whisper** — оптимизированная версия Whisper на CTranslate2
- **Размер модели:** small (460 МБ) — баланс скорости и качества
- **Квантование:** int8 — экономия RAM и ускорение на CPU
- **VAD-фильтр:** автоматическое отбрасывание тишины и пауз

### Метрики

#### Основные метрики

| Метрика | Формула | Назначение |
| :--- | :--- | :--- |
| **WER** | `(S + D + I) / N` | % ошибочных слов (основная метрика) |
| **CER** | `(s + d + i) / n` | % ошибочных символов (точнее для некоторых языков) |

Где:
- **S (Substitutions)** — замены слов ("дом" → "том")
- **D (Deletions)** — пропуски слов
- **I (Insertions)** — вставка лишних слов
- **N** — общее количество слов в эталоне

#### Ручная реализация S/D/I

**Проблема:** API `jiwer` менялось 3 раза за проект (`wer_details` → `compute_measures` → `process_words`), и каждый раз код ломался.

**Решение:** Реализован **алгоритм Левенштейна** (динамическое программирование) для расчета S/D/I/.

**Алгоритм:**
1. Строится матрица редактирующих расстояний между словами reference и hypothesis
2. Обратным проходом восстанавливается тип каждой операции (hit/sub/del/ins)
3. Возвращается точная статистика ошибок

### Текстовая нормализация

**Проблема:** Whisper по умолчанию:
- Добавляет заглавную букву в начале
- Расставляет точки и запятые
- Преобразует числа в цифры ("двести сорок пять" → "245")

Без нормализации **WER на чистых аудио был 42%** — модель распознавала идеально, но скрипт считал пунктуацию и регистр ошибками.

**Решение:**

```python
def normalize_text(text: str) -> str:
    text = text.lower()
    text = re.sub(r'[^\w\s]', '', text)  # удаление пунктуации
    return " ".join(text.split())
```

Результат: WER на чистых аудио упал до ожидаемых 5-10%.

## Запуск

1. Установка зависимостей

```bash
pip install -r requirements.txt
```

Важно: Используется av==13.1.0 для совместимости с faster-whisper.

2. Запуск оценки

### Базовый запуск (модель скачается автоматически)

```bash
python evaluate_asr.py
```

### С указанием модели и тестового набора

```bash
python evaluate_asr.py --model small --test-set test_set.jsonl
```

Доступные модели: tiny, base, small, medium, large-v3
Для 8GB RAM и CPU рекомендуется: small (460 МБ)

## Анализ результатов

Чистые аудио: WER ~5-10% — отличное качество для модели small на CPU.
Шумные аудио: WER ~80% — значительная деградация качества.

Ключевой диагностический вывод: В шуме доминируют Substitutions (замены), а не Deletions (пропуски). Это значит, что модель слышит речь, но разбирает слова неточно из-за акустических искажений.

Рекомендация: Не увеличивать модель, а добавить шумоподавление на pre-processing.

## Технические детали

Оптимизация для CPU:
- Квантование int8 — уменьшает потребление RAM с ~1.8 ГБ до ~460 МБ
- VAD-фильтр — отбрасывает тишину, ускоряет обработку
- Latency: ~1.8с на 5-секундный клип на i5-1135G7
